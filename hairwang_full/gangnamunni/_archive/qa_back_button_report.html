Root cause: Samsung Android OS auto-restarts the Activity after Activity.finish() or Dart VM crash (exit(0)). finishAffinity() closes ALL Activities in the task stack, telling the OS the entire task is complete — no restart.

Android 14 Special Handling

Android 14 introduces the Predictive Back Gesture API which changes how back events are routed:

Manifest FlagdispatchKeyEventOnBackPressedCallbackPopScope
enableOnBackInvokedCallback="true"Not called for BACKCalled once onlyUnreliable
enableOnBackInvokedCallback="false"WorksWorksWorks

Fix: Set enableOnBackInvokedCallback="false" in AndroidManifest.xml (patient/admin apps). This makes dispatchKeyEvent catch KEYCODE_BACK on Android 14, enabling reliable double-press detection.

Troubleshooting Timeline

Attempt 1
SystemNavigator.pop() — Samsung OS restarts Activity after finish()
Attempt 2
exit(0) — OS treats as crash, restarts Activity
Attempt 3
Flutter MethodChannel bidirectional — Native→Flutter→Native silently fails
Attempt 4
enableOnBackInvokedCallback="true" — Android 14 dispatchKeyEvent not called, OnBackPressedCallback fires once only
Final Solution
enableOnBackInvokedCallback="false" + dispatchKeyEvent + native finishAffinity() — works on all Android versions

iOS Status

iOS has no hardware back button. The swipe-to-go-back gesture is handled natively by Flutter's Navigator. The finishAffinity() fix is Android-only. iOS apps do not require changes for this issue.
