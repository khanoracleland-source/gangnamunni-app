③ 3-레이어 캡처 아키텍처

레이어 A — 웹 + WebView 앱 즉시 가능 (Playwright)

  • 대상: gangnamunni 웹 / 네이티브 통합앱(WebView) / 관리자앱(WebView)
  • 도구: Playwright + 모바일 디바이스 에뮬레이션(iPhone 14 / Galaxy S24 뷰포트)
  • 캡처: 각 단계 page.screenshot() + 세션 전체 recordVideo(.webm) 동시 수집
  • 로그인/가입: 폼 자동 입력 (기존 엔진의 자동 감지 로직 재사용)

레이어 B — 네이티브 Flutter 앱 (환자/파트너) Maestro 설치 후

  • 대상: com.wellness.customer(환자) · com.wellness.vendor(파트너) — 실기기 SM-N981N
  • 도구: Maestro(YAML 플로우, Android+iOS 공용, 단계별 스크린샷 내장) + adb screenrecord(동영상) + adb exec-out screencap
  • 요소 식별: GetX 패턴 — 텍스트/AppBar 타이틀/필드 순서로 탭·입력 (survey에서 식별자 확보)
  • iOS: 동일 Maestro 플로우를 Mac에서 iPhone 대상 실행

레이어 C — 자가검수 (Claude) 신규

  • 캡처 후 모든 이미지 ≤900px 리사이즈(PIL, 세션 중단 방지 — 프로젝트 규칙)
  • run_manifest.json 생성: [{step, screen, action, expected, screenshot, video_ts}]
  • Claude가 각 스크린샷을 기대값과 대조해 한 장씩 판정: PASS / FAIL / 의심 + 사유
  • 판정 결과를 HTML 리포트로(이미지+판정+동영상 플레이어 임베드)
  • 루프: FAIL 발견 → 원인 수정 → 재실행 → 전부 PASS까지 반복

④ 테스트 시나리오 — 환자앱 풀 플로우 (대표)

각 단계 = 스크린샷 1+장 + 동영상 구간. 식별자는 소스 조사 기반(signin_screen.dart 등).

자가검수 판정 항목 (단계별)

  • 화면이 의도한 단계와 일치하는가 (제목/주요 요소 존재)
  • PHP/JS 에러·빈 화면·깨진 레이아웃·잘림 없음
  • 입력값이 정상 반영·검증 메시지 정상
  • 전환(다음 화면 진입)이 성공했는가
  • (선택) Figma 시안 대비 시각적 일치도
✅ 전 단계 PASS → 해당 빌드는 스토어 재제출 적격. Android는 키스토어 보유로 AAB 즉시 빌드, iOS는 Mac에서 Archive→App Store Connect 업로드.
