WebView base URL — Gnuboard \$connect 파라미터 충돌
지적 앱이 메인 도메인에 쿼리 파라미터를 붙여 로딩할 때 connect=android가 들어가면 500 에러 발생 위험
원인서버 루트가 Gnuboard 위에 올라가 있어 'connect'라는 쿼리/세션 변수명이 Gnuboard 내부 DB 핸들 변수 \$connect와 충돌. 실측: https://...gangnamunni/?connect=android → HTTP 500, 반면 ?app_connect=android → HTTP 200. 네이티브 리패키징 시 메모리(native_app_repackage)대로 connect=android → app_connect=android로 이미 교체했고, 현재 앱 소스(MainActivity.java)는 connect=android를 직접 구성하지 않음(grep 0건). 단 서버측 500 버그는 잠재적으로 남아있어 외부 링크/푸시 딥링크가 connect= 를 달면 재발.
해결방법앱 측: 추가 작업 불필요(app_connect 사용 확인됨). 서버 측(컨펌 필요 — 정상 동작 중 백엔드 변경): Gnuboard 루트 진입 스크립트(common.php/_common.php 인근)에서 외부 GET 파라미터 'connect'를 내부 \$connect로 덮어쓰지 않도록 가드 추가(예: 진입부에서 unset(\$_GET['connect']) 또는 변수 분리). 차선책: 앱/푸시 측에서 절대 connect= 파라미터를 URL에 붙이지 않는 규칙 고정(현재 준수 중).
