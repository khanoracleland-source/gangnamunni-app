3. 협업 규칙 제안 — GitHub 브랜치 분리 방식

충돌 방지의 가장 안전한 방식은 "파일 경로 단위 작업 영역 분리"입니다. FTP 폴더 분리는 동일 파일을 양쪽이 만지면 덮어쓰기 사고가 발생하므로 비추천드리며, Git 브랜치 + 파일 영역 분리를 함께 적용하면 사실상 충돌 가능성이 0에 가깝습니다.

3-3. 머지 및 충돌 시 처리 규칙

  1. 매일 18:00 동기화 — 각자 자기 브랜치를 master로 머지 (Pull Request 기반)
  2. 충돌 발생 시: 발생 알림 → 30분 내 협의 → 해당 파일은 우선 작업자 기준 머지, 다른 쪽은 rebase
  3. 긴급 수정(hotfix): hotfix/* 브랜치로 즉시 분기 → master 머지 → 양쪽 브랜치에 rebase
  4. 배포 권한: 서버 배포는 개발팀이 일괄 (담당자님 PR 머지 후 24시간 내 반영)
