서울미녀 앱 1차 검수 — 전체 수정 시나리오 (작업 분해)

작성일 : 2026-05-28 (목)
목적 : 약 100건의 수정 작업이 왜 약 6주(개발) + 2주(검수) = 8주가 필요한지 작업 단위 분해로 설명
기준 시트 : 1차 검수 명세서
관련 문서 : 마일스톤 상세

왜 약 6주(개발)가 필요한가?

각 수정 항목은 단순히 "버그 픽스 한 줄" 처럼 보이지만, 실제로는 ① 원인 분석 → ② 수정 → ③ 회귀 테스트 → ④ 배포 → ⑤ 양 OS(iOS/Android) 검증의 5단계를 거쳐야 합니다. 또한 한 화면을 건드리면 연관된 데이터/탭/권한도 함께 검증해야 하므로, 한 항목당 평균 처리 시간이 최소 30분 ~ 최대 4시간 사이로 분포합니다.

아래는 100건의 작업을 난이도별·항목별로 분해한 시나리오입니다. 단순 작업과 복잡 작업이 섞여 있어 전체 시간이 누적됩니다.

1. 항목별 표준 처리 5단계 (단순 "수정" ≠ 30분)

단순한 픽스라도 안전한 배포를 위해 다음 5단계를 거쳐야 합니다.

1 원인 분석 10~60분
  • 증상 재현 (Android SM-A135N + iOS iPhone XS 양쪽)
  • 관련 PHP/JS/CSS 코드 파악, 로그 추적
  • DB 스키마 확인 (gangnamunni_*, hospital_*, g5_*)
  • 유사 케이스/연관 페이지 영향도 점검
2 수정 작업 20분~3시간
  • PHP 서버 코드 수정 (Prepared Statement, 권한 체크, 세션 처리)
  • JS/CSS 프론트 수정 (Bootstrap 5.3.3 + vanilla JS, 다크모드 호환)
  • DB 마이그레이션 필요 시 SQL 작성 + 백업 + 적용
  • 관리자 화면 측 연동 (RBAC 권한 9역할 고려)
3 회귀 테스트 15~45분
  • 수정 화면 동작 확인 (정상/엣지케이스/에러 핸들링)
  • 연관 페이지 회귀 테스트 (관련된 3~5개 화면)
  • 관리자 화면 RBAC 권한별 동작 확인
  • 로그인 상태/비로그인 상태 양쪽 검증
4 서버 배포 5~15분
  • paramiko SFTP + base64 인코딩 → SSH 디코딩 → CRLF 제거
  • php -l 신택스 검증
  • Apache reload 또는 캐시 클리어
  • 도메인 호출로 정상 응답 확인
5 양 OS 검증 + 보고 10~30분
  • Android (SM-A135N) 실기기 설치 후 동작 확인
  • iOS (iPhone XS) 실기기 설치 후 동작 확인 (필요 시 빌드 재서명)
  • 수정 전/후 캡처 비교
  • 변경 이력 기록 (admin_fix_log)
⏱ 1개 항목 평균 처리 시간 = 약 1.5시간 ~ 3시간 (단순 ~ 중간 복잡도 기준)

3. 전체 작업 시간 누적 계산

단순 합산
개발 270시간 ÷ 8시간/일 = 약 34일 (순수 작업일)

하지만 이는 "100% 코딩만 한다는 가정". 실무에서는 다음 요소가 추가됩니다.

실무에서 추가되는 요소
구분시간 영향설명
① 회귀 버그 발견 시 추가 수정+10~15%한 항목 수정 시 다른 화면 깨짐 발견되어 추가 픽스 필요
② 시트 외 동반 발견 이슈+10%"동반 개선" 원칙에 따라 같은 화면 사소한 UI 깨짐 함께 정리
③ 양 OS 빌드 재서명/업로드+2일iOS 인증서/프로비저닝, Android keystore, 스토어 업로드
④ 검수자측 피드백 응답 대기+가변사양 확정/이미지 확인 등 일부 항목은 검수자 답변 대기
⑤ 주말/공휴일-주말주 5일 작업 기준, 주말은 작업일에서 제외
📐 개발 기간 산정 : 34일 × 1.2 (회귀+동반) + 2일 (양OS 빌드) = 약 43일 작업일 ≈ 6주 (주말 제외)
🔍 검수 기간 산정 : 검수자측 1차 검수 1주 + 피드백 최종 반영 1주 = 2주
⏱ 합계 : 개발 6주 + 검수 2주 = 총 8주 (2026-05-27 ~ 07-21)

8. 종합 — 왜 8주가 안전 마진인가

① 단순 합산은 6주가 빠듯하다

개발 작업 누적 시간 270시간 = 34일 (8시간/일 기준). 여기에 회귀 +10%, 동반 작업 +10%, 양 OS 빌드 +2일이 더해져 약 43일 = 약 6주가 됩니다. 이미 안전 마진은 거의 없습니다.

② "단순 항목 많은데 왜 오래 걸리나" — 누적 효과

0.5시간짜리 25건 = 12.5시간 (1.5일), 2.5시간짜리 50건 = 125시간 (15.6일), 5시간짜리 25건 = 125시간 (15.6일). 단순 항목이 많아도 중간/복잡 항목이 50%를 차지하므로 시간이 길어집니다.

③ "왜 휴일에 가능한 것부터 했다고 하면서 시간이 더 필요한가"

5/21~5/26 휴일 기간에 처리한 것은 난이도 단순 항목 중 일부 (배너 패딩, 플로팅 버튼 숨김, DEV 데이터 삭제 등)입니다. 이미 이 부분은 Phase 3에서 차감된 일정이며, 복잡 항목과 양 OS 빌드/검수는 압축이 불가능합니다.

④ 조기 완료 가능성

본 시나리오는 안전 마진을 포함한 보수적 예측입니다. 실제 작업에서 회귀 버그가 적게 발생하거나 복잡 항목이 단순화되면 일정이 1~2주 단축될 수 있습니다. 각 Phase 종료 시 진행 상황을 공유하며, 일찍 끝나면 검수 단계도 그만큼 앞당겨 시작합니다.

📌 결론 : 100건 = 단순한 픽스가 아니라, 평균 2.5시간/건 × 100건 + 양 OS 빌드 + 검수 = 8주가 안전 일정.
그러나 실제로는 6~7주 사이 완료 가능성이 높으며, 진행 상황은 매주 보고드립니다.
