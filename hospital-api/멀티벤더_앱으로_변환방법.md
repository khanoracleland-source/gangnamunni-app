## 1. 프로젝트 개요

### 1.1 변환 목표
- **현재**: Kivicare는 단일 병원용 의료 관리 시스템
- **목표**: 여러 병원(클리닉)을 관리할 수 있는 멀티벤더 시스템으로 변환
- **참조**: Frezka 멀티벤더 구조를 기반으로 branch_id → clinic_id 개념으로 변환

### 1.2 핵심 변경 사항
- 모든 병원 관련 데이터에 `clinic_id` 또는 `vendor_id` 추가
- 사용자가 로그인하면 해당 병원의 데이터만 조회
- 병원별 데이터 격리 및 권한 관리 강화
- 관리자(admin)는 전체 병원 데이터 접근 가능

```php
public function branches()
{
    return $this->hasMany(BranchEmployee::class, 'employee_id');

public function scopeBranch($query)
{

    if (isset($branch_id)) {
```

```php
protected static function boot()
{
    parent::boot();

    // vendor 필터링을 위한 글로벌 스코프
    static::addGlobalScope('vendor', function ($builder) {
        if (app()->bound('active_vendor') && $vendor = app('active_vendor')) {
            $builder->where('vendor_id', $vendor->id);
        }
    });
```

### 4.3 마이그레이션 파일 생성 예시

각 테이블에 clinic_id를 추가하는 마이그레이션 파일 예시:

```php
<?php

use Illuminate\Database\Migrations\Migration;
use Illuminate\Database\Schema\Blueprint;
use Illuminate\Support\Facades\Schema;

return new class extends Migration
{
    public function up()
    {
        // appointment_transactions 테이블에 clinic_id 추가
        Schema::table('appointment_transactions', function (Blueprint $table) {
            $table->unsignedBigInteger('clinic_id')->nullable()->after('appointment_id');
            $table->index('clinic_id');

            // 외래키 제약 조건 (선택사항)
            $table->foreign('clinic_id')
                  ->references('id')
                  ->on('clinic')
                  ->onDelete('cascade');
        });

        // 기존 데이터에 clinic_id 업데이트
        // appointments 테이블에서 clinic_id를 가져와서 설정
        DB::statement("
            UPDATE appointment_transactions at
            INNER JOIN appointments a ON at.appointment_id = a.id
            SET at.clinic_id = a.clinic_id
            WHERE at.clinic_id IS NULL
        ");

        // clinic_id를 NOT NULL로 변경 (선택사항)
        Schema::table('appointment_transactions', function (Blueprint $table) {
            $table->unsignedBigInteger('clinic_id')->nullable(false)->change();
        });
    }

    public function down()
    {
        Schema::table('appointment_transactions', function (Blueprint $table) {
            $table->dropForeign(['clinic_id']);
            $table->dropColumn('clinic_id');
        });
```

### 4.4 데이터 마이그레이션 전략

기존 데이터가 있는 경우 다음 단계로 진행:

1. **백업**: 전체 데이터베이스 백업
2. **clinic_id 추가**: NULL 허용으로 컬럼 추가
3. **데이터 업데이트**: 기존 데이터에 clinic_id 값 채우기
   - 단일 병원 시스템이었다면 모든 데이터를 기본 clinic_id로 설정
   - 연관 테이블에서 JOIN을 통해 clinic_id 가져오기
4. **NOT NULL 변경**: clinic_id를 필수 컬럼으로 변경
5. **인덱스 추가**: clinic_id에 인덱스 추가 (성능 향상)
6. **외래키 추가**: clinic_id와 clinic 테이블 간 외래키 제약 조건 추가

### 5.3 미들웨어(Middleware) 추가

병원 선택 및 세션 관리를 위한 미들웨어:

```php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;

class SetCurrentClinic
{
    public function handle(Request $request, Closure $next)
    {
        if (auth()->check() && multiVendor() == "1") {
            $user = auth()->user();

            // 세션에 current_clinic_id가 없으면 설정
            if (!session()->has('current_clinic_id')) {
                $clinicId = $this->getDefaultClinicId($user);

                if ($clinicId) {
                    session(['current_clinic_id' => $clinicId]);
                }
            }

            // URL에 clinic_id 파라미터가 있으면 세션 업데이트
            if ($request->has('clinic_id') && $this->canAccessClinic($user, $request->clinic_id)) {
                session(['current_clinic_id' => $request->clinic_id]);
            }
        }

        return $next($request);
    }

    private function getDefaultClinicId($user)
    {
        if ($user->hasRole('vendor')) {
            return \Modules\Clinic\Models\Clinics::where('vendor_id', $user->id)->first()->id ?? null;
        }

        if ($user->hasRole('doctor')) {
            return \Modules\Clinic\Models\DoctorClinicMapping::where('doctor_id', $user->id)
                                                              ->first()
                                                              ->clinic_id ?? null;
        }

        if ($user->hasRole('receptionist')) {
            return \Modules\Clinic\Models\Receptionist::where('receptionist_id', $user->id)
                                                       ->first()
                                                       ->clinic_id ?? null;
        }

        return null;
    }

    private function canAccessClinic($user, $clinicId)
    {
        if ($user->hasRole(['admin', 'demo_admin'])) {
            return true;
        }

        if ($user->hasRole('vendor')) {
            return \Modules\Clinic\Models\Clinics::where('vendor_id', $user->id)
                                                  ->where('id', $clinicId)
                                                  ->exists();
        }

        if ($user->hasRole('doctor')) {
            return \Modules\Clinic\Models\DoctorClinicMapping::where('doctor_id', $user->id)
                                                              ->where('clinic_id', $clinicId)
                                                              ->exists();
        }

        if ($user->hasRole('receptionist')) {
            return \Modules\Clinic\Models\Receptionist::where('receptionist_id', $user->id)
                                                       ->where('clinic_id', $clinicId)
                                                       ->exists();
        }

        return false;
    }
}
```

## 6. 인증 및 권한 관리

### 6.1 역할(Role) 정의

Kivicare에서 이미 정의된 역할들:
- **admin**: 전체 시스템 관리자 (모든 병원 접근 가능)
- **demo_admin**: 데모 관리자
- **vendor**: 병원 소유자 (자신의 병원들만 관리)
- **doctor**: 의사 (자신이 속한 병원들만 접근)
- **receptionist**: 수용실 담당자 (자신이 속한 병원만 접근)
- **patient**: 환자 (자신의 데이터만 접근)
- **pharma**: 약사

### 6.2 권한(Permission) 관리

#### 6.2.1 병원별 권한 분리
각 역할에 따라 접근 가능한 병원 범위를 제한:

| 역할 | 접근 범위 | clinic_id 필터링 |
|-----|----------|----------------|
| admin | 모든 병원 | 필터링 없음 |
| vendor | 자신이 소유한 병원들 | clinic.vendor_id = user.id |
| doctor | 자신이 속한 병원들 | doctor_clinic_mapping.doctor_id = user.id |
| receptionist | 자신이 속한 병원 | receptionist.clinic_id |
| patient | 자신의 진료 기록 | appointments.user_id = user.id |

#### 6.2.2 Policy 클래스 생성

각 모델에 대한 Policy 생성:

```php
<?php

namespace App\Policies;

use App\Models\User;
use Modules\Appointment\Models\Appointment;

class AppointmentPolicy
{
    public function viewAny(User $user)
    {
        // 모든 사용자가 자신의 권한 범위 내에서 예약 목록 조회 가능
        return true;
    }

    public function view(User $user, Appointment $appointment)
    {
        // admin은 모든 예약 조회 가능
        if ($user->hasRole(['admin', 'demo_admin'])) {
            return true;
        }

        // vendor는 자신의 병원 예약만
        if ($user->hasRole('vendor')) {
            return $appointment->clinic->vendor_id == $user->id;
        }

        // doctor는 자신이 담당하는 예약만
        if ($user->hasRole('doctor')) {
            return $appointment->doctor_id == $user->id;
        }

        // receptionist는 자신의 병원 예약만
        if ($user->hasRole('receptionist')) {
            $receptionist = \Modules\Clinic\Models\Receptionist::where('receptionist_id', $user->id)->first();
            return $receptionist && $appointment->clinic_id == $receptionist->clinic_id;
        }

        // patient는 자신의 예약만
        if ($user->hasRole('patient')) {
            return $appointment->user_id == $user->id;
        }

        return false;
    }

    public function create(User $user)
    {
        // 환자를 제외한 모든 역할이 예약 생성 가능
        return !$user->hasRole('patient');
    }

    public function update(User $user, Appointment $appointment)
    {
        // view 권한과 동일
        return $this->view($user, $appointment);
    }

    public function delete(User $user, Appointment $appointment)
    {
        // admin과 예약을 생성한 사용자만 삭제 가능
        return $user->hasRole(['admin', 'demo_admin']) ||
               $appointment->created_by == $user->id;
    }
}
```
